# Платежи

## Telegram Stars (реализовано, по умолчанию выключено)

Поток (`app/services/payments.py`, `app/bot/handlers.py`):

1. Пользователь принимает условия (`/terms` → «Akceptuję regulamin»), без этого счёт не создаётся.
2. `/plan` → «Kup …» → бот отправляет счёт `sendInvoice` с `currency="XTR"`, пустым `provider_token`
   и payload `sub:<plan>:<telegram_id>:<цена>:<nonce>`.
3. `pre_checkout_query` → проверка payload, валюты, суммы, владельца счёта, актуальной цены и статуса
   тарифа, блокировки пользователя → `answerPreCheckoutQuery` (ответ укладывается в 10 секунд).
4. Доступ выдаётся **только** после `successful_payment`: событие записывается в `payment_events`
   (уникально по `telegram_payment_charge_id`), создаётся запись `payments`, активируется/продлевается
   подписка — всё в одной транзакции. Повтор того же события → «уже учтено», доступ второй раз не выдаётся.
5. Возврат: `/refund <charge_id> [причина]` (админ) → `refundStarPayment` → платёж `refunded`,
   подписка, оплаченная этим платежом, отзывается. Неудачный возврат пишется в `refunds` и журнал.

Правила периода (`app/domain/plans.py::compute_new_period`):
* продление того же тарифа добавляется к концу текущего периода;
* смена тарифа действует сразу, неиспользованная стоимость старого тарифа переводится в дополнительное
  время нового (пропорционально цене); пробный период не конвертируется;
* после окончания подписки мониторинг останавливается, поиски сохраняются; пользователь получает одно
  уведомление об окончании.

### Режимы (`PAYMENTS_MODE`)

| Режим | Что происходит |
|---|---|
| `disabled` (по умолчанию) | Кнопки покупки скрыты, счета не создаются. Админ может выдать доступ `/grant`. |
| `test` | Бот работает с **тестовой средой Telegram** (`api.telegram.org/bot<token>/test/...`). Нужен отдельный бот, созданный в тестовом DC. Реальные деньги не списываются. |
| `live` | Реальные Stars. Включается только вместе с `PAYMENTS_LIVE_CONFIRMED=yes`. **Не включать без решения владельца.** |

Как получить тестового бота: создать аккаунт в тестовой среде Telegram (на странице
https://core.telegram.org/bots/payments-stars есть ссылка на инструкцию по тестовой среде), создать там бота у @BotFather и поставить его токен
в `BOT_TOKEN` вместе с `PAYMENTS_MODE=test`. Токен обычного (боевого) бота в режиме `test` работать не будет.

## Криптовалюта (заблокировано)

Документация Telegram (https://core.telegram.org/bots/payments-stars): цифровые товары и услуги в ботах
продаются только за Stars; сторонние провайдеры и криптовалюта не допускаются, в том числе через
собственный сайт. Подписка этого бота — цифровая услуга, поэтому криптооплата **не подключена**.

Что сделано, чтобы не блокировать архитектуру:
* `app/services/crypto.py`: интерфейс `CryptoProvider`, `MockCryptoProvider`, проверка HMAC-подписи
  вебхука, классификация недоплаты/переплаты/неверной сети;
* `POST /webhooks/crypto` возвращает 404, пока `CRYPTO_ENABLED=false`; при включении только проверяет
  подпись и идемпотентно сохраняет событие — **доступ не выдаёт**.

Для включения нужно: юридическое подтверждение допустимого сценария, выбор провайдера с
документированным API, реализация выдачи доступа с проверкой суммы/валюты/сети/статуса.
Приватные ключи и seed-фразы не хранятся в проекте ни при каких условиях.
