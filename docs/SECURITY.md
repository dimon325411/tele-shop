# Безопасность и эксплуатация

## Секреты
* Все секреты — только в `.env` (в `.gitignore`) или в переменных окружения сервера. В репозитории есть
  лишь `.env.example` без настоящих значений.
* Логи проходят через `SecretFilter` (`app/logging_setup.py`): токены бота и пароли в DSN маскируются.
  `Settings.safe_dict()` выводит конфигурацию без секретов.
* Пользователям никогда не показываются технические ошибки — только общее сообщение и `/support`.

## Ротация секретов
| Секрет | Как сменить |
|---|---|
| `BOT_TOKEN` | @BotFather → `/revoke` → новый токен в `.env` → `docker compose up -d bot worker` |
| `POSTGRES_PASSWORD` | `docker compose exec postgres psql -U market -c "ALTER USER market PASSWORD '...'"` → обновить `.env` → перезапустить `bot worker api` |
| `CRYPTO_WEBHOOK_SECRET` | сменить у провайдера и в `.env` одновременно, перезапустить `api` |
После утечки: сменить секрет, проверить `/audit` и логи, при необходимости сделать резервную копию до изменений.

## Доступ и права
* Администраторы определяются по числовому Telegram ID (`ADMIN_IDS`), не по username.
* Все проверки тарифа, лимитов и владения поиском выполняются в сервисах на сервере
  (`app/services/*`, `app/domain/plans.py`), кнопки интерфейса ничего не решают.
* Каждое действие администратора пишется в `admin_audit_log` (`/audit`).
* Ограничение частоты команд: `COMMAND_RATE_PER_MINUTE` на пользователя (token bucket).
* Заблокированный пользователь может только читать `/terms`, `/privacy`, `/support`, `/paysupport`.

## Вебхуки и сеть
* Бот работает через long polling — входящий Telegram-вебхук не нужен.
* HTTP API (`/health`, `/ready`, `/webhooks/crypto`) опубликован только на `127.0.0.1:8080`;
  наружу — через reverse proxy с TLS, если нужно.
* Вебхук криптопровайдера выключен; при включении проверяется HMAC-SHA256 подпись в постоянное время.

## Персональные данные и сроки хранения
Храним: Telegram ID, username, имя, настройки поисков, историю уведомлений и платежей. Не храним
телефон и геолокацию. Сроки (настраиваются в `.env`): объявления 30 дней, журнал проверок 14 дней,
уведомления 90 дней (ежедневная задача `retention`).

Удаление аккаунта (`/settings` → «Usuń konto»): удаляются поиски, совпадения и уведомления, профиль
обезличивается, активная подписка отменяется. Записи о платежах сохраняются для бухгалтерии и
возвратов (до 5 лет по польскому законодательству — уточнить у бухгалтера).

## Источники
Запросы к площадкам выполняются только для разрешённых источников. Клиент `app/sources/http.py`
соблюдает интервал между запросами, тайм-ауты, при 403/429/CAPTCHA останавливает сбор и не пытается
обойти защиту. Сейчас реальные площадки отключены (см. `docs/SOURCES.md`).
